Manual de Usuario - Portfolio Web

Bienvenido al manual operativo de tu Portfolio Web. Este documento contiene toda la información necesaria para arrancar, configurar y mantener tu página web.

1. Arquitectura del Sistema

El proyecto está dividido en dos partes principales, comunicadas a través de una API REST:

  • Frontend (Carpeta frontend): Interfaz de usuario construida con React, TypeScript y Vite. Utiliza TailwindCSS para los estilos y Framer Motion para las animaciones.
  • Backend (Carpeta backend): Servidor construido con Node.js, Express y TypeScript. Se encarga de la base de datos, correos y panel de administración.
  • Base de Datos: SQLite (archivo local portfolio.db). Gestionado con Prisma ORM.

2. Arrancar el Proyecto Localmente

Para probar y modificar el proyecto en tu ordenador, he preparado unos scripts automáticos (archivos .bat) en la carpeta principal:

  • ARRANCAR_TODO.bat: Instala las dependencias si faltan, genera la base de datos y arranca el frontend y el backend al mismo tiempo. Usa este script siempre que quieras trabajar.
  • CERRAR_TODO.bat: Cierra de forma segura todos los procesos de Node.js en tu ordenador por si algo se queda colgado.
  • VERIFICAR_SISTEMA.bat: Chequea que tienes Node.js instalado y que los puertos están libres.

Una vez arrancado, podrás acceder a:

  • Web: http://localhost:5173
  • Backend API: http://localhost:4000/api

3. Configuración del Formulario de Contacto (Resend)

El formulario de la web utiliza la API gratuita de Resend para enviarte los mensajes por correo, esquivando los bloqueos de los servidores gratuitos (como Railway).

Importante: Para que funcione correctamente en producción, debes asegurarte de que la clave de Resend esté configurada en las Variables de Entorno.

En el panel de tu servidor (Railway o Vercel backend), añade la siguiente variable:

RESEND_API_KEY=re_tu_clave_secreta_aqui

El correo destino al que llegarán los mensajes será siempre baciapez@gmail.com.

4. Panel de Administración y Contenido

El portfolio incluye un panel de administración para gestionar proyectos, experiencia y tu perfil (si lo tienes activado en las rutas). Si deseas inyectar o reiniciar los datos de demostración (LinguaCore, etc.), el sistema lo hace de forma automática la primera vez que se crea la base de datos gracias a los archivos inject-projects.ts en el backend.

5. Guía de Despliegue (Producción)

El sistema está optimizado para desplegarse de la siguiente forma:

5.1 Frontend (Vercel recomendado)

  1. Conecta tu repositorio de GitHub a Vercel.
  2. Selecciona la carpeta frontend como "Root Directory".
  3. El framework debe ser "Vite".
  4. En variables de entorno, añade: VITE_API_URL=https://tu-url-del-backend.railway.app/api

5.2 Backend (Railway recomendado)

  1. Conecta tu GitHub a Railway y despliega la carpeta backend.
  2. Añade un Volumen en Railway para que el archivo de base de datos SQLite no se borre al reiniciar el servidor. Monta el volumen en /app/data o similar.
  3. Variables de entorno clave: 
    PORT=8080
DATABASE_URL=file:/app/data/portfolio.db
NODE_ENV=production
CORS_ORIGIN=https://tu-url-del-frontend.vercel.app
RESEND_API_KEY=re_tu_clave...

6. Resolución de Problemas Comunes (FAQ)

Problema Solución
Al enviar el formulario dice "Error de conexión" o "Timeout". Asegúrate de que la API de Resend está puesta y que el backend está encendido. Revisa los logs de Railway por si hubiera un fallo en el token.
La web carga pero los proyectos no aparecen. El frontend no se está pudiendo comunicar con el backend. Verifica que VITE_API_URL apunta correctamente a la URL pública de tu backend.
Los cambios en el código no se ven reflejados localmente. Refresca la caché del navegador (Ctrl+F5) o asegúrate de que el terminal donde arrancaste ARRANCAR_TODO.bat no haya mostrado errores.
